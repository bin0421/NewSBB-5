[2] 결정 사항
-------------
1. 템플릿 : create-next-app 16.4.6 (TypeScript, App Router, src/ 폴더, Tailwind CSS, ESLint, Turbopack, 경로 별칭 @/*), 패키지 관리자 npm.
   폴더 이름에 대문자가 있어 npm 패키지 이름은 newsbb-5 로 한다.
2. 참고 범위 : 강의 slog.gg/p/14175 1~34강, 강사 저장소 jhs512/p-14175-3 의 034-2 커밋까지.
   화면 문구와 동작은 강사 코드를 따른다. 백엔드는 jhs512/p-14172-2 를 그대로 쓴다 (http://localhost:8080).
3. 단계 : 요구한 9개 기능을 요구한 순서대로 002~010 으로 매긴다. 001 은 프로젝트 생성과 테스트 환경 구성이다.
   설명만 있는 강의 회차(서버·클라이언트 컴포넌트, 동기·비동기 등)는 따로 단계로 만들지 않는다.
4. TDD : 기능마다 -1 테스트 추가 (실패) / -2 구현 (통과) / 필요할 때만 -3 리팩터링.
   테스트만 넣은 커밋은 의도한 이유로 실패하는지 확인하고 README 에 실패 이유를 적는다.
5. 테스트 도구 : Vitest + React Testing Library (jsdom), user-event, jest-dom.
   fetch 와 next/navigation(useRouter, useParams)을 가짜로 바꿔 백엔드 없이 테스트한다.
6. 강사 코드와 다르게 한 것
   - 007-3 : 글 작성·수정 폼을 공통 컴포넌트 PostForm 으로 분리
   - 008-2 : 댓글 목록·삭제·작성을 PostCommentSection 컴포넌트로 분리 (댓글 요청은 글을 불러온 뒤 시작)
   - 009-2, 010-2 : 댓글 상태를 함수형 업데이트로 변경
7. .env 는 비밀 값이 없으므로 강의 20강처럼 버전 관리에 넣는다. 테스트에서는 vitest.config.mts 의 test.env 로 같은 값을 쓴다.
8. @types/node 는 vitest 5 의 요구(22 이상)에 맞춰 24 로 올린다.
9. 35~51강(강사 저장소 035~051 커밋) : "참고사항을 그대로 따라하지 말 것" 을 강의의 개선점(유효성 검사 세분화, API 오류 처리,
   상세 페이지 리팩터링, 댓글 수정, 댓글 여러 줄 표시)은 반영하되 코드는 이 저장소의 구조에 맞게 직접 설계한다는 뜻으로 본다.
   단계는 011 부터 이어서 매긴다. 기능이 바뀌는 단계는 -1 테스트 (실패) / -2 구현,
   리팩터링 단계는 테스트를 바꾸지 않고 기존 테스트가 그대로 통과하는 커밋 하나로 한다.
10. 35~51강에서 강사 코드와 다르게 하는 것
   - 011 : 길이 규칙을 한 모듈에 모아 글쓰기·글 수정·댓글 폼이 함께 쓴다 (강의 : 페이지마다 if 문 복사)
   - 012 : 실패 응답을 Error 를 상속한 ApiError(resultCode, msg) 로 reject 한다 (강의 : 응답 객체를 그대로 throw)
   - 013~015 : 훅은 src/hooks/ 에 파일로 둔다. 하위 컴포넌트에는 훅 결과 통째(ReturnType)가 아니라 필요한 값·함수만 props 로 넘긴다
   - 016-3 : 댓글 작성·수정이 같은 댓글 폼 컴포넌트를 쓴다 (강의 : 폼과 검사 코드를 두 벌)
11. 자동 진행 범위 : 승인한 단계 목록(011~017)은 묻지 않고 구현 -> 검증 -> 커밋 -> 푸시한다. 헷갈리는 점이 생기면 그때 묻는다.
